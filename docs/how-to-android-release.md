# Как настроить подпись релизной сборки Android

Эта инструкция — для шага 3.1. Архитектурное решение и причины подробно описаны в
[ADR 0005](decisions/0005-android-release-signing.md); здесь только порядок действий.

**Важно:** ключ и пароли создаёте и храните **вы сами**, руками, вне репозитория. Ни один
агент (Claude Code) не создаёт, не читает и не видит эти файлы — так требует `CLAUDE.md`.
Всё, что ниже, вы выполняете в своём терминале самостоятельно.

## 1. Что такое keystore и зачем он нужен

*Keystore* («хранилище ключей») — это файл с секретным ключом, которым подписывается APK
перед установкой. Android разрешает ставить обновление поверх уже установленного приложения,
только если новая версия подписана **тем же** ключом — поэтому ключ создаётся один раз и
бережно хранится, а не генерируется заново для каждой сборки.

## 2. Создать хранилище ключей командой `keytool`

`keytool` — утилита из комплекта JDK (Java Development Kit), который ставится вместе с
Android Studio, отдельно скачивать ничего не нужно. Точный путь к нему на этой машине можно
посмотреть командой:

```powershell
flutter doctor -v
```

— в выводе рядом с Android toolchain будет путь к Android Studio; JDK обычно лежит внутри
неё, например `...\Android Studio\jbr\bin\keytool.exe`. Если такой путь найден, добавьте его
в команду ниже вместо просто `keytool`; если `keytool` уже виден в `PATH` (проверить командой
`keytool -version`), можно вызывать его по имени.

Команда для создания хранилища `zuno-release.jks` (ключ RSA 2048 бит, срок действия
10 000 дней — как решено в ADR 0005, раздел 1):

```powershell
keytool -genkeypair -v -storetype JKS -keystore D:\Android\keys\zuno-release.jks `
    -alias zuno -keyalg RSA -keysize 2048 -validity 10000
```

`keytool` спросит пароль хранилища, пароль ключа (можно сделать одинаковым) и несколько
вопросов про «имя и фамилию», «организацию» и т. д. — для личного проекта подойдут любые
осмысленные ответы, на работу подписи они не влияют.

## 3. Куда класть файл

Каталог `D:\Android\keys\` нужно создать заранее (`New-Item -ItemType Directory -Force
D:\Android\keys`), если его ещё нет. Это тот же диск D:, где уже лежат Android SDK
(`D:\Android\Sdk`) и кэш Gradle (`D:\Android\gradle`) — на этой машине всё тяжёлое и приватное
вынесено на диск D:, а не C:. Главное правило: файл должен быть **вне каталога репозитория**
`D:\Projects\Claude\MoneyAPP`, чтобы его нельзя было случайно закоммитить.

## 4. Файл `zuno-keystore.properties`

Рядом с ключом (тоже в `D:\Android\keys\`, тоже вне репозитория) создайте текстовый файл
`zuno-keystore.properties` с четырьмя строками:

```properties
storeFile=D:\\Android\\keys\\zuno-release.jks
storePassword=ваш_пароль_хранилища
keyAlias=zuno
keyPassword=ваш_пароль_ключа
```

**Важно про слэши.** Java-формат `.properties` разбирает одиночный обратный слэш `\` как
начало экранированной последовательности (как `\n` для новой строки), поэтому путь Windows
нужно писать либо двойным обратным слэшем `\\`, либо обычными прямыми слэшами:
`storeFile=D:/Android/keys/zuno-release.jks` — оба варианта работают одинаково, выбирайте
любой, но не одиночный `\`.

## 5. Переменная окружения `ZUNO_KEYSTORE_PROPERTIES`

Gradle (система сборки Android) находит файл из пункта 4 по переменной окружения
`ZUNO_KEYSTORE_PROPERTIES` — в ней должен лежать полный путь к `zuno-keystore.properties`.

Задать переменную **для своего пользователя** (не для всей системы — так не нужны права
администратора, и настройка не действует на других пользователей этого компьютера) можно
одним из двух способов:

- через панель управления: «Изменение переменных среды текущего пользователя» → «Создать» →
  имя `ZUNO_KEYSTORE_PROPERTIES`, значение — путь к файлу;
- или командой PowerShell (тоже только для текущего пользователя, `User`, а не `Machine`):

  ```powershell
  [Environment]::SetEnvironmentVariable(
      'ZUNO_KEYSTORE_PROPERTIES',
      'D:\Android\keys\zuno-keystore.properties',
      'User'
  )
  ```

**После этого обязательно откройте новый терминал** (PowerShell читает переменные окружения
только при старте, уже открытое окно их не увидит) и, если Android Studio была открыта во
время настройки — перезапустите и её тоже, по той же причине.

## 6. Проверка, что всё получилось

1. Хранилище ключей создано и содержит алиас `zuno`:

   ```powershell
   keytool -list -v -keystore D:\Android\keys\zuno-release.jks
   ```

   В выводе должна быть строка с именем алиаса `zuno`.

2. В **новом** окне PowerShell переменная видна:

   ```powershell
   echo $env:ZUNO_KEYSTORE_PROPERTIES
   ```

   Должен напечататься путь к `zuno-keystore.properties`.

3. В репозитории ничего лишнего не появилось:

   ```powershell
   git status
   ```

   Вывод должен быть чистым — ни `.jks`, ни `.properties` файлов в списке быть не должно
   (они и не могут там появиться, так как лежат в `D:\Android\keys\`, вне репозитория).

## 7. Резервные копии ключа — обязательно

Это самый важный пункт инструкции. **Ключ нельзя сгенерировать заново** — новый ключ будет
уже *другим* ключом, и Android откажется ставить с ним обновление поверх уже установленного
приложения.

Что это значит на практике, если ключ потерян (сломался диск, переустановлена Windows и т. п.):
обновить приложение на телефоне станет невозможно. Единственный выход — удалить приложение и
поставить заново с новым ключом, а удаление уничтожает **все данные**, потому что:

- Android Auto Backup у приложения выключен (`allowBackup="false"`, решение ADR 0001) —
  копии в Google-аккаунте нет;
- экспорта в CSV на момент этапа 3 тоже ещё нет (появится отдельным мини-этапом сразу после).

Поэтому сразу после создания ключа сделайте **минимум две резервные копии** файлов
`zuno-release.jks` и `zuno-keystore.properties`, в местах, не привязанных к этому компьютеру.
Например:

- одна копия — в менеджере паролей (как вложение или заметка), который у вас уже есть для
  других паролей;
- вторая копия — на внешнем диске или в облачном хранилище (Google Drive, Dropbox и т. п.),
  отдельно от рабочего компьютера.

Пароли из `zuno-keystore.properties` тоже стоит сохранить в менеджере паролей отдельно —
на случай, если файл скопирован, а какой из паролей к нему относится, забылось.

## 8. Как выпустить следующую сборку

Перед **каждой** установкой новой сборки на телефон номер сборки нужно увеличить на 1 — это
число `+N` в конце строки `version` в `pubspec.yaml` (например, `0.1.0+1` → `0.1.0+2`).
Android не даст установить APK с тем же или меньшим номером сборки поверх уже установленного
приложения. Сама версия (`0.1.0`) при этом может не меняться, пока не понадобится отдельно
отметить содержательный релиз.
