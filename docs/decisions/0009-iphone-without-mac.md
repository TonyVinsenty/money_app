# 0009. iPhone без Mac: облачная сборка, бесплатная подпись, сохранность данных, импорт CSV

- Статус: принято пользователем 2026-10-05
- Дата: 2026-10-05
- Решения пользователя 2026-10-05: инструмент — Sideloadly (инструкция максимально пошаговая, первую установку ассистент ведёт вместе с пользователем); выбор файла для импорта — **своё окно выбора файла** на Swift и Kotlin (п. 5, отличается от первоначальной рекомендации «папка в „Файлах“»); неизвестные категории создаются автоматически; повторная загрузка ничего не задваивает; при ошибках в файле не загружается ничего; дата позже сегодняшней — ошибка; резервная копия iCloud/Finder остаётся; напоминание — только строка «Последняя выгрузка» в «Настройках».

Связанные решения: [0001](0001-local-storage-drift.md) (база в каталоге поддержки приложения, резервное копирование), [0003](0003-dependencies.md) (пакеты, нативный код как главный риск), [0004](0004-money-dates-recurring.md) (деньги и даты), [0006](0006-csv-export-format.md) (формат CSV, свой Android-код вместо `share_plus`). План — `docs/ROADMAP.md`, «Мини-этап „iPhone“», шаги i.1–i.19.

## Контекст

Основной телефон пользователя — iPhone (решение 2026-10-05). Ограничения:

- **Mac нет.** Собрать iOS-приложение можно только на macOS с Xcode. Значит, сборка — только в облаке, а Swift-код и настройки iOS на машине разработчика не проверить ничем, кроме нашего Dart-теста по тексту файлов.
- **Apple Developer Program нет.** TestFlight и App Store недоступны. Остаётся **бесплатная подпись своим Apple ID**: пользователь ставит сборку с Windows через Sideloadly или AltStore, установка живёт 7 дней, потом её надо переподписать.
- **Под iOS проект ни разу не собирался.** Что уже есть в `ios/` (проверено 2026-10-05): шаблон Flutter 3.47.5 со сценами (`SceneDelegate.swift`, `FlutterImplicitEngineDelegate` в `AppDelegate.swift`), плагины подключаются через Swift Package Manager (`FlutterGeneratedPluginSwiftPackage`, `Podfile` нет), `IPHONEOS_DEPLOYMENT_TARGET = 15.0`, `TARGETED_DEVICE_FAMILY = "1,2"` (iPhone и iPad), bundle id `com.tonyvinsenty.zuno`, в `Info.plist` видимое имя «Zuno» и только портретная ориентация.
- **Нативные части:** `path_provider` (плагин команды Flutter), `sqlite3` (сам приносит SQLite через build hooks, при сборке скачивает готовую библиотеку с github.com — в облаке это не проблема). Экспорт CSV отправляется **своим Android-кодом** по каналу `com.tonyvinsenty.zuno/share` (ADR 0006); на iOS обработчика этого канала нет — кнопка экспорта сейчас упадёт с `MissingPluginException`. `share_plus` в проекте нет.
- **Репозиторий `github.com/TonyVinsenty/money_app` публичный** (проверено 2026-10-05). Для публичных репозиториев стандартные облачные машины GitHub Actions, включая macOS, бесплатны (документация GitHub, проверено 2026-10-05).
- **Главное требование пользователя: данные на iPhone не теряются при обновлениях.** Резервной копии на сервере нет (local-first), единственная копия, которой управляем мы, — экспорт CSV.
- Импорт CSV перенесён из этапа 6 сюда: пользователь переделает выгрузку из прежнего приложения в наш формат и загрузит её на iPhone.
- Схема базы v1 выпущена; этот ADR её **не меняет**.

## Решение

### 1. Облачная сборка — GitHub Actions, ручной запуск

Файл `.github/workflows/ios-build.yml`:

- запуск **только вручную** (`workflow_dispatch`: вкладка Actions → «iOS build» → Run workflow); на каждый коммит не собираем;
- машина — macOS-образ GitHub с **явно указанной версией** (не `macos-latest`, чтобы сборка не сломалась сама при смене образа); конкретный образ выбирается в шаге i.2 по документации GitHub и требованиям Flutter 3.47.5 к Xcode;
- Flutter ставится **без сторонних actions**: `git clone --depth 1 --branch 3.47.5 https://github.com/flutter/flutter.git`; из чужого кода — только официальные `actions/checkout` и `actions/upload-artifact`. Права workflow — `contents: read`, секретов нет;
- `flutter pub get` → `flutter build ios --release --no-codesign` (сборка **без подписи**: подписывает потом Sideloadly на компьютере пользователя);
- **сторож bundle id**: после сборки `PlistBuddy` читает `CFBundleIdentifier` и `CFBundleDisplayName` из собранного `Runner.app/Info.plist`; если это не `com.tonyvinsenty.zuno` и не «Zuno» — сборка падает с понятным текстом. В журнал печатаются версия и номер сборки;
- упаковка: папка `Payload/` с `Runner.app` внутри, сжатая в zip, называется `Zuno-<версия>-<номер>.ipa` (`.ipa` — это и есть zip с такой папкой);
- артефакт хранится 14 дней (`retention-days: 14`).

**Номер сборки** берётся из `pubspec.yaml` (`version: 0.1.0+N`), как на Android: правило «каждая установка на телефон = +1» общее для обеих платформ. Номер запуска workflow не используем — тогда номер в приложении расходился бы с `pubspec.yaml`.

**Облако собирает то, что лежит на GitHub.** Перед запуском коммиты надо отправить (`git push`). По `CLAUDE.md` агенты не делают `push` без прямой просьбы, поэтому это делает пользователь или агент по его явной просьбе.

**Если репозиторий станет приватным**, бесплатные минуты кончатся быстро: macOS-минута стоит примерно в 10 раз дороже Linux-минуты, а на бесплатный план GitHub даёт 2000 минут в месяц на всё. Запасной вариант — Codemagic: бесплатно 500 минут macOS M2 в месяц для личного аккаунта (проверено 2026-10-05). Заранее его не настраиваем.

**Чтобы bundle id не поменялся случайно в проекте**, есть ещё Dart-тест-сторож (шаг i.1), он работает на Windows в обычном `flutter test`. Тест читает `ios/Runner.xcodeproj/project.pbxproj` и `ios/Runner/Info.plist` и проверяет:

- `PRODUCT_BUNDLE_IDENTIFIER = com.tonyvinsenty.zuno` во всех трёх конфигурациях цели `Runner`;
- `CFBundleIdentifier = $(PRODUCT_BUNDLE_IDENTIFIER)`;
- видимое имя «Zuno»;
- только портретная ориентация.

Так же устроен сторож `build.gradle.kts` из шага 3.2.

### 2. Установка — Sideloadly с одним и тем же Apple ID

Инструмент — **Sideloadly** (решение пользователя 2026-10-05: «самое простое и бесплатное»; инструкция пишется по одному действию на шаг, первую установку ассистент ведёт вместе с пользователем) (Windows; нужны iTunes и iCloud в версиях **с сайта Apple, а не из Microsoft Store** — так требует сам Sideloadly). Причины:

- на iPhone не ставится лишнее приложение. AltStore сам занимает одно из трёх мест, доступных бесплатному Apple ID;
- Sideloadly ставит `.ipa` с компьютера напрямую, а переподписывать может сам, в фоне (auto-refresh), если компьютер включён и iPhone в той же сети Wi-Fi.

AltStore — запасной вариант. **Смешивать инструменты нельзя** (см. п. 3). Пошаговая инструкция — `docs/how-to-iphone.md` (шаг i.4).

Ограничения бесплатной подписи (по документации AltStore и Sideloadly, проверено 2026-10-05): установка действует **7 дней**; одновременно активны **не больше 3** установленных так приложений; не больше **10 App ID** за 7 дней. На iOS 16 и новее нужно один раз включить «Режим разработчика» и доверить свой Apple ID в «Настройки → Основные → VPN и управление устройством». Возможности, которым нужны особые права (iCloud, push-уведомления), бесплатной подписи недоступны. Нам они не нужны: всё, что мы добавляем (п. 4–5), — обычные ключи `Info.plist`, а не права подписи.

### 3. Сохранность данных при обновлениях (главное требование)

**От чего зависит.** iOS хранит данные приложения (база `zuno.sqlite` в каталоге поддержки, папка «Документы») в **контейнере**. Контейнер привязан к **bundle id** на этом iPhone. Новая сборка с тем же bundle id от той же «команды разработчика» (бесплатный Apple ID = своя команда) ставится **поверх**: это обновление, контейнер остаётся.

| Что случилось | Что с данными |
|---|---|
| Новая сборка поставлена поверх: тот же инструмент, тот же Apple ID, тот же bundle id | **сохраняются** |
| Прошло 7 дней, подпись истекла | **сохраняются**; приложение не открывается до переподписи |
| Переподпись (refresh) или установка той же сборки заново | **сохраняются** |
| Сертификат отозван (например, вход тем же Apple ID в другом инструменте, лимит сертификатов) | **сохраняются**; приложение не открывается, пока его не поставят поверх заново |
| iOS «сгрузила» неиспользуемое приложение | **сохраняются**; вернуть — установка поверх через Sideloadly |
| В Sideloadly включена смена bundle id или установка сделана другим инструментом (AltStore для бесплатного аккаунта, по нашим сведениям, дописывает к идентификатору ID команды — **не проверено**, проверяем по факту) | на экране **вторая иконка «Zuno» с пустой базой**; старые данные остаются в старой копии, пока её не удалили |
| Сборка подписана **другим Apple ID** (другая команда) | iOS не даёт поставить поверх: идентификатор не совпадает. Придётся удалить старое приложение — **данные потеряны**, если нет CSV |
| Приложение удалено | **данные удалены** (iOS об этом предупреждает) |
| bundle id изменён в проекте | для iPhone это другое приложение, как в строке со второй иконкой. **Запрещено**, ловят два сторожа (п. 1) |

**Защита (всё вместе):**

1. Два сторожа bundle id: Dart-тест в репозитории и проверка в облачной сборке (п. 1).
2. Правила в `docs/how-to-iphone.md`, отдельным заметным блоком:
   - всегда Sideloadly и один и тот же Apple ID (записать, какой);
   - опция смены bundle id выключена;
   - обновлять только установкой поверх, приложение **не удалять**;
   - «появилась вторая иконка Zuno — остановиться, старую не удалять, сделать экспорт из старой».
3. **Перед каждой установкой — экспорт CSV** и сохранение файла вне телефона (Telegram «Избранное», почта, компьютер). Это первый пункт короткого чек-листа «Как поставить обновление» в инструкции.
4. Строка **«Последняя выгрузка: 5 октября»** рядом с кнопкой экспорта в «Настройках» (шаг i.8). Дата хранится в таблице настроек `app_settings` новым ключом, **без миграции схемы**. Плашки-напоминания на «Главной» нет (решение пользователя 2026-10-05).
5. **Проверка на тестовых данных до настоящих** (шаг i.5): поставить сборку, внести 2–3 тестовые операции, поставить следующую сборку поверх и убедиться, что операции на месте. Только после этого и после работающего экспорта (i.7) вносятся настоящие данные.

### 4. Экспорт на iOS — свой Swift-код в том же канале

Канал прежний: `com.tonyvinsenty.zuno/share`, метод `shareCsvFile` с аргументом `path`. Dart-код (`share_csv_file.dart`) не меняется. В `ios/Runner/AppDelegate.swift`:

- в `didInitializeImplicitFlutterEngine` создаётся `FlutterMethodChannel` на `engineBridge.applicationRegistrar.messenger()` — так рекомендует документация Flutter для шаблона со сценами (docs.flutter.dev, миграция на `UIScene`);
- обработчик проверяет, что файл есть (иначе ошибка `file_not_found`, как на Android), и показывает системный лист «Поделиться» (`UIActivityViewController`) с URL файла поверх корневого экрана активной сцены;
- для iPad обязательно задаётся точка привязки всплывающего окна (`popoverPresentationController.sourceView`), иначе на iPad приложение падает. Сборка остаётся для iPhone и iPad, `project.pbxproj` не трогаем;
- ответ в Dart уходит сразу после показа листа, результат не ждём — так же, как на Android.

Ориентир — около 40 строк Swift (и ещё около 60 — окно выбора файла, п. 5). **Код пишем прямо в `AppDelegate.swift`, без новых `.swift`-файлов**: новый файл нужно прописать в `project.pbxproj`, а без Xcode это ручная правка служебного файла, которую не проверить.

Вместе с этим в `Info.plist` добавляется `CFBundleLocalizations` со значением `ru`. Без него iOS считает приложение англоязычным и показывает системные окна («Поделиться», «Сохранить в Файлы», выбор файла) по-английски даже на русском iPhone.

### 5. Выбор файла для импорта — своё системное окно выбора файла (решение пользователя 2026-10-05)

Кнопка «Загрузить из CSV» открывает **системное окно выбора файла**: «На iPhone», iCloud Drive, «Загрузки» и т. д. Сделано своим кодом, без пакетов, через отдельный канал `com.tonyvinsenty.zuno/files` с методом `pickCsvFile`. Ответ — путь к **копии** выбранного файла во временном каталоге приложения или `null`, если пользователь нажал «Отмена». Дальше файл читает Dart (`dart:io`), а после закрытия экрана импорта копия удаляется.

- **iOS** (`AppDelegate.swift`, около 60 строк, без новых `.swift`-файлов): `UIDocumentPickerViewController(forOpeningContentTypes: [.commaSeparatedText, .plainText], asCopy: true)`. С `asCopy: true` iOS сама копирует файл в каталог приложения, поэтому особые права доступа к чужому файлу не нужны. Делегат окна и ожидающий ответ Dart хранятся в свойствах `AppDelegate`: иначе делегат уничтожится и ответ не придёт никогда. Второй вызов, пока окно открыто, — ошибка `busy`.
- **Android** (`MainActivity.kt`, около 50 строк): `ACTION_OPEN_DOCUMENT` с `CATEGORY_OPENABLE` и типами `text/csv`, `text/comma-separated-values`, `text/plain`; содержимое копируется потоком в `cacheDir`. Импорт на Android не обязателен (данные там тестовые), но делаем его, и **раньше iOS** (шаг i.13 до i.14). Это единственный способ пройти весь импорт целиком на эмуляторе — без цикла «облако → iPhone» — и загрузить туда тестовый набор данных. Swift-обработчик потом повторяет уже проверенную логику.
- **Dart**: обёртка `pickCsvFile` с типом-функцией `PickFile` (как `ShareFile` у экспорта), чтобы экраны тестировались с фейком. Сама обёртка тестируется на фейковом канале. Сторож-тест проверяет, что имена канала и метода в Dart, `MainActivity.kt` и `AppDelegate.swift` совпадают.
- Ключи `UIFileSharingEnabled`/`LSSupportsOpeningDocumentsInPlace` **не добавляются**: папка приложения в «Файлах» не нужна.

Сравнение с вариантами «папка в „Файлах“» и `file_picker` — в «Отвергнутых», п. 8–9.

### 6. Импорт CSV — правила

Формат — ровно формат экспорта (ADR 0006, п. 2 и 6). Для пользователя он описан в `docs/csv-format.md` с примером (шаг i.9).

**Чтение файла.**

- UTF-8 с BOM или без. Файл не в UTF-8 (например, Excel сохранил «CSV (разделители — запятые)» в кодировке Windows) — ошибка с подсказкой, как сохранить правильно.
- Разделитель определяется по строке заголовков: `;` (наш экспорт, русский Excel) или `,` («Google Таблицы»). Для этого чтение кодека получает параметр-разделитель; запись не меняется.

**Заголовки.**

- Колонки ищутся по имени, без учёта регистра и пробелов по краям; лишние колонки пропускаются.
- Обязательные: `Дата`, `Тип`, `Сумма`, `Категория`. Нет обязательной или одна колонка повторяется — ошибка всего файла.

**Номер строки в ошибке** = номер строки в Excel (заголовки — строка 1). Комментарий с переносом строки занимает в Excel одну строку, поэтому номер считается по записям, а не по строкам текста.

**Значения:**

| Колонка | Правило |
|---|---|
| `Дата` | `ДД.ММ.ГГГГ`, день и месяц можно одной цифрой (`4.10.2026`); несуществующая дата — ошибка. Дата позже сегодняшней — ошибка, как при ручном вводе (решение пользователя) |
| `Тип` | `Расход` или `Доход`, регистр не важен |
| `Сумма` | разбирает `parseAmount` (`350`, `350,5`, `1 234,56`, `350.00`). Минус допустим только у расхода и отбрасывается (направление задаёт `Тип`); минус у дохода — ошибка. Тексты ошибок — те же, что при вводе суммы |
| `Валюта` | пусто → `RUB`; любая другая валюта — ошибка (приложение пока только рублёвое) |
| `Категория` / `Подкатегория` | не пусто / можно пусто; до 40 символов, как в приложении |
| `Комментарий` | пробелы по краям обрезаются, пусто → нет комментария; длиннее 200 символов — ошибка (не обрезаем молча) |
| `ID …` | если есть — в формате UUID; один `ID операции` дважды в файле — ошибка |
| `Время операции (UTC)` | если есть и его местный день совпадает с `Дата` — берём его; иначе момент считается из даты тем же правилом, что при ручном вводе задним числом (`Occurrence`) |

**Сначала проверка всего файла, потом запись.** Ничего не пишется, пока не проверены все строки. Найденные ошибки показываются списком «Строка 15: сумма „12.3.4“ — не число»: первые 20 и «… и ещё N». Если есть хоть одна ошибка, **не загружается ничего** — исправьте файл и загрузите снова (решение пользователя; вариант «загрузить хорошие строки» отвергнут, п. 11).

**Категории** ищутся в таком порядке:

1. по `ID категории`, если такая категория есть в базе (в том числе в архиве). Если её вид не совпадает с `Тип` или это подкатегория — ошибка строки;
2. по виду и имени (без учёта регистра и пробелов по краям) среди не архивных категорий верхнего уровня;
3. не нашлась — **создаётся**: с id из файла, если он есть и свободен, иначе с новым; иконка по умолчанию, в конце списка. Подкатегории — так же, внутри своей категории.

Предпросмотр заранее перечисляет категории, которые будут созданы (решение пользователя: создавать автоматически). Операция, попавшая по id в **архивную** категорию, загружается в неё, а категория остаётся в архиве: это история, как и при экспорте (ADR 0006, п. 3). Правило «новую операцию в архивную категорию нельзя» (дополнение ADR 0001, веха 2B) защищает выбор категории на экране; импорт проходит мимо него отдельным явным методом записи, и на это есть тесты.

**Дубли при повторном импорте** (решение пользователя: ничего не задваивать):

- `ID операции` уже есть в базе — строка пропускается («уже есть»). Если та операция удалена в приложении — тоже пропускается, отдельным счётчиком: удаление уважаем. Отличия в полях не переносим (обновления нет).
- **Строка без `ID операции`** (файл, сделанный руками) получает **«отпечаток»** — id, вычисленный из самой строки: дата, тип, сумма, категория, подкатегория, комментарий и порядковый номер среди одинаковых строк файла (UUID версии 5, его умеет уже подключённый пакет `uuid`). Повторная загрузка того же файла даёт те же id, и строки пропускаются как «уже есть». Две одинаковые покупки в один день (порядковые номера 1 и 2) остаются двумя операциями.

**Предпросмотр перед записью**: «Будет добавлено 1 234 операции, пропущено 12 (уже есть), будут созданы категории: Расходы — Аптека, Бензин; Доходы — Кэшбэк». Кнопки «Загрузить» и «Отмена».

**Запись — одна транзакция drift.** Создание категорий и операций либо проходит целиком, либо откатывается целиком; после отката база такая же, как до импорта. Репозитории работают поверх одной и той же базы, а вложенная транзакция в drift присоединяется к внешней.

**Схема не меняется.** Всё ложится в существующие таблицы `categories` и `transactions`.

### 7. Резервная копия iCloud и Finder — остаётся (решение пользователя 2026-10-05)

`zuno.sqlite` лежит в каталоге поддержки приложения. iOS по умолчанию включает его в резервную копию iCloud и копию на компьютере. На Android Auto Backup выключен решением пользователя от 2026-09-20.

**На iPhone не выключаем** (рекомендация принята пользователем). Причины:

- для установки с бесплатной подписью риск потерять данные выше, чем для приложения из App Store (7 дней, отзыв сертификата, ошибка с Apple ID), и любая лишняя копия полезна;
- пользователь сам управляет этим в настройках iPhone («Настройки → [имя] → iCloud → Резервная копия → приложения»). Это и есть его явное решение, а local-first-принцип про «наш» сервер не нарушается.

Честная оговорка в инструкции: восстановление данных приложения, поставленного **не из App Store**, из резервной копии iPhone **не гарантировано**. Главная копия по-прежнему — CSV.

Если пользователь когда-нибудь решит исключить базу из копии, это 5–10 строк Swift (`isExcludedFromBackup` для файла базы при каждом запуске) отдельным шагом, с той же цепочкой «сборка в облаке → проверка на iPhone».

## Последствия

**Становится проще:**

- iPhone получает приложение без Mac и без платного аккаунта; облачная сборка бесплатна, пока репозиторий публичный.
- Новых пакетов нет. Нативного Swift-кода около 100 строк, в одном файле, и каждый обработчик повторяет Kotlin-обработчик, проверенный на эмуляторе.
- Окно выбора файла привычное (системное, с iCloud Drive). Вся логика импорта — чистый Dart с тестами на Windows, а весь путь импорта проходится на эмуляторе. Проверка «экспорт → импорт в пустую базу → снова экспорт даёт побайтно тот же файл» доказывает, что резервная копия действительно восстанавливается.
- Сохранность данных держится на трёх независимых вещах: сторожах bundle id, правилах в инструкции и регулярном CSV.

**Становится сложнее:**

- Цикл проверки iOS-изменения длинный: коммит → `push` → облачная сборка (около 15–25 минут) → скачать → Sideloadly → проверить руками. Поэтому iOS-шаги делаем маленькими и редкими.
- Каждые 7 дней — переподпись (или auto-refresh Sideloadly). Пропустил — приложение не открывается, пока не переподпишешь; данные целы.
- Swift и `Info.plist` на Windows проверяются только тестом-сторожем по тексту файлов. Ошибка компиляции видна только в облаке, ошибка поведения — только на iPhone.
- Окно выбора файла на iOS — второй кусок Swift, который ведёт себя правильно или нет только на iPhone: делегат должен жить, пока окно открыто, а ответ в Dart должен прийти ровно один раз. Проверяется пунктом чек-листа iPhone.

**Риски:**

| Риск | Что делаем |
|---|---|
| Первая iOS-сборка не собирается (SPM, хуки `sqlite3`, версия Xcode) | шаг i.3 — только сборка, без новых функций; правки — шагом i.3b, по одной за запуск |
| Swift-код компилируется, но не работает | кода мало, каждый обработчик повторяет Android-обработчик, проверенный на эмуляторе; ручная проверка экспорта на iPhone (i.7) до того, как от него зависят настоящие данные; окно выбора файла — пункт чек-листа iPhone (i.18); запасной путь для импорта — папка «Zuno» в «Файлах» (отвергнутый вариант 9) |
| Данные потеряны при обновлении | п. 3: сторожа, правила, экспорт перед установкой, проверка на тестовых данных (i.5) |
| Apple изменит правила бесплатной подписи или Sideloadly перестанет работать | запасной путь — AltStore (переход только через экспорт и импорт CSV, см. п. 3); в перспективе — Apple Developer Program |
| Импорт испортит базу | проверка всего файла до записи, одна транзакция, предпросмотр, тест «туда и обратно»; перед импортом — экспорт |
| Репозиторий станет приватным | Codemagic, 500 бесплатных минут macOS в месяц |

## Отвергнутые варианты

**1. Codemagic как основной CI.** Удобный интерфейс, 500 бесплатных минут macOS. Но это ещё один внешний аккаунт и настройки вне репозитория. GitHub Actions уже рядом с кодом, workflow лежит в репозитории и виден в истории, а для публичного репозитория бесплатен без лимита минут. Codemagic остаётся запасным.

**2. Подпись прямо в CI (Apple ID и пароль в секретах GitHub, `fastlane`).** Отвергнуто: пароль Apple ID в облаке — недопустимый риск, бесплатную подпись в CI всё равно пришлось бы обновлять раз в 7 дней, а `fastlane` — тяжёлая зависимость. Подписывает Sideloadly на компьютере пользователя.

**3. Сторонний action для установки Flutter (`subosito/flutter-action`).** Популярный и с кэшем, но это чужой код, который выполняется с доступом к репозиторию. `git clone` нужной версии Flutter занимает пару минут и обходится без него.

**4. Номер сборки из номера запуска workflow.** Номер в приложении разошёлся бы с `pubspec.yaml` и с Android-сборками. Отвергнуто.

**5. TestFlight.** Требует Apple Developer Program, которого нет. Вернёмся, если программа будет оформлена: тогда переход с бесплатной подписи на платную команду — **через экспорт и импорт CSV** (другая команда = другое приложение для iOS, п. 3).

**6. AltStore как основной инструмент.** Умеет переподписывать с самого iPhone, но сам занимает одно из трёх мест бесплатного Apple ID и, по нашим сведениям, меняет bundle id. Оставлен запасным.

**7. `share_plus` только ради iOS.** Пакет подключился бы и к Android, где мы от него ушли (ADR 0006: Telegram открывался внутри окна Zuno на Huawei/Honor). Получилось бы два механизма «Поделиться» на ~40 строк Swift. Отвергнуто.

**8. Выбор файла пакетом `file_picker`** (13.1.0, издатель `victorcarreras.dev` с проверкой, 160 points, MIT, на iOS требует 14.0+; проверено на pub.dev 2026-10-05). В ADR 0003 он разрешён для импорта, но это ещё одна нативная зависимость с отдельными реализациями под каждую платформу. Её поведение на iOS мы проверим только на iPhone, как и своё, но в своём коде мы видим всё, а системное окно выбора файла — это около 60 строк Swift. Остаётся запасным вариантом, если своё окно не заработает, — с отдельным согласием пользователя.

**9. Папка «Zuno» в приложении «Файлы»** (`UIFileSharingEnabled` + `LSSupportsOpeningDocumentsInPlace`, экран со списком `*.csv` из «Документов» приложения). Это была первоначальная рекомендация архитектора: ноль нативного кода. Пользователь 2026-10-05 выбрал своё окно выбора файла — привычнее, без лишнего шага «сначала положи файл в папку Zuno». Вариант остаётся запасным, если Swift-окно не заработает.

**10. «Открыть в Zuno» из других приложений (`CFBundleDocumentTypes` и обработка ссылки в `SceneDelegate`).** Удобно (Telegram → «Открыть в Zuno»), но нужно ловить файл и при холодном, и при «тёплом» запуске и передавать его в Dart. Это самый сложный и самый непроверяемый на Windows вариант. Отвергнут для первой версии.

**11. Импорт «хорошие строки загрузить, плохие пропустить».** Тихо неполная история хуже честного отказа (тот же принцип, что у экспорта, ADR 0006, п. 3). Пользователь 2026-10-05 выбрал «всё или ничего».

**12. Защита от дублей сравнением по содержимому с базой** (та же дата, сумма, категория). Ловит и операции, внесённые руками, но ложно срабатывает на настоящих повторах (два кофе в день) и требует от пользователя решать каждый случай. «Отпечаток» строки проще и предсказуем.

**13. Проверка bundle id внутри приложения во время работы.** Новая копия с другим bundle id живёт в другом контейнере и ничего не знает о старой — предупреждать не о чем. Пользу дают правило «вторая иконка — стоп» и экспорт перед обновлением, а не код.
