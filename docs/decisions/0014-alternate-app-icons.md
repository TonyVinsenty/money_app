# 0014. Выбор иконки приложения в «Настройках» своим нативным кодом

- Статус: предложено (ждёт согласия пользователя; вопрос «какая иконка по умолчанию» — `docs/ROADMAP.md`, «Этап 8 — вопросы к пользователю»)
- Дата: 2026-10-14

Дополняет [ADR 0013](0013-polish-design-system.md), п. 9 (иконка «Кольцо»: рисунок, адаптивный значок Android, одна картинка 1024 на iOS, сторож формата) и [ADR 0009](0009-iphone-without-mac.md) (iOS собирается только в облаке, Mac нет). Не меняет ADR 0002 (слои и состояние), схему базы v3 и формат CSV. **Новых пакетов нет.** Шаги — `docs/ROADMAP.md`, «Этап 8 «Глубокая полировка» — шаги», пачки 7 и 8.

## Контекст

В глубоком анализе этапа 8 (`docs/design-review-stage8.md`, раздел 9) `ui-designer` нарисовал 10 вариантов иконки. Пользователь 2026-10-14 выбрал четыре и попросил дать выбор между ними в «Настройках»:

| id (не меняется никогда) | Вариант из раздела 9 | Название в приложении (черновик) |
|---|---|---|
| `ring` | 1. Кольцо крупнее | «Кольцо» |
| `ring_blue` | 2. Кольцо на синем | «Кольцо на синем» |
| `coins` | 6. Монеты | «Монеты» |
| `wallet` | 7. Кошелёк | «Кошелёк» |

Нынешний вариант 0 (мелкое кольцо) пользователь не отметил, поэтому иконку по умолчанию заменяет один из четырёх (рекомендация — `ring`, самый близкий к нынешнему знаку; решает пользователь).

Ограничения:

- Без пакетов (принцип 5). Нативный код iOS — только `ios/Runner/AppDelegate.swift`; Android — `MainActivity.kt`.
- iOS собирается в облаке без подписи, подписывает Sideloadly бесплатным Apple ID (ADR 0009). Проверить iOS-часть можно только облачной сборкой и на iPhone пользователя.
- Смена иконки — системная возможность, у каждой платформы своя: на iOS это `UIApplication.setAlternateIconName`, на Android «настоящей» смены иконки нет — только включение и выключение заранее описанных в манифесте ярлыков (`activity-alias`).

## Решение

### 1. Источник истины — сама система, а не база

Какая иконка сейчас стоит, приложение каждый раз спрашивает у системы (iOS — `alternateIconName`, Android — какой ярлык включён). В базе и в `app_settings` выбор не хранится: так не бывает расхождения «в настройках одно, на рабочем столе другое» (например, после переустановки). Миграций нет.

### 2. Канал `com.tonyvinsenty.zuno/app_icon`

Новый канал по образцу `links` и `reminders` (шаг 8.0, ADR 0011, п. 11):

- `current` → строка `id` из таблицы выше (или `null`, если система не умеет менять иконку);
- `set` с аргументом `{"id": "<id>"}` → `true` / `false`;
- `supported` → `true` / `false` (iOS — `UIApplication.shared.supportsAlternateIcons`, Android — всегда `true`).

Соответствие `id` → имя на платформе знает только нативный код. Сторож-тест (как сторож канала напоминаний) сверяет список `id` в Dart, Kotlin, Swift, в `AndroidManifest.xml` и в `project.pbxproj`.

Dart-сторона: `lib/features/settings/domain/app_icon_choice.dart` (перечисление четырёх вариантов со стабильными `id`, чистый Dart), `lib/features/settings/data/app_icon_channel.dart` (вызовы канала, ошибки и отсутствие канала → «не поддерживается»), строка и лист выбора — в `settings_screen.dart` (или отдельном виджете рядом).

### 3. iOS — альтернативные наборы иконок в каталоге ресурсов

- В `ios/Runner/Assets.xcassets/` рядом с `AppIcon.appiconset` (иконка по умолчанию) — ещё три набора, по одной картинке 1024 × 1024 **без альфа-канала** (как в ADR 0013, п. 9): `AppIcon-RingBlue`, `AppIcon-Coins`, `AppIcon-Wallet` (точные имена — по выбору иконки по умолчанию; набор по умолчанию всегда называется `AppIcon`).
- В `ios/Runner.xcodeproj/project.pbxproj` у трёх конфигураций Runner (Debug, Release, Profile — там, где уже стоит `ASSETCATALOG_COMPILER_APPICON_NAME = AppIcon`) добавляется `ASSETCATALOG_COMPILER_ALTERNATE_APPICON_NAMES = "AppIcon-RingBlue AppIcon-Coins AppIcon-Wallet"`. Xcode (13+) сам кладёт картинки в сборку и сам дописывает в `Info.plist` раздел `CFBundleIcons` → `CFBundleAlternateIcons`. Каталог ресурсов уже входит в цель Runner, новые файлы в проект добавлять не нужно.
- Swift: `set` вызывает `UIApplication.shared.setAlternateIconName(nil | "AppIcon-…")` на главном потоке и отвечает в Dart из обработчика завершения; `current` читает `alternateIconName` (`nil` → иконка по умолчанию).
- **iOS сама показывает окно «Вы изменили значок «Zuno»» — убрать его нельзя** (обходы через закрытые API не берём). Это нормальное поведение, приложение не закрывается.
- В облачной сборке (`.github/workflows/ios-build.yml`) — новая проверка рядом с проверкой bundle id: в собранном `Info.plist` есть `CFBundleIcons:CFBundleAlternateIcons` и в нём три ожидаемых имени (`PlistBuddy`). Если Xcode наборы не подхватил, сборка падает с понятной ошибкой, а не тихо выпускает приложение без иконок.
- Тёмный и «тонированный» варианты iOS 18+ не рисуем (как ADR 0013, п. 9) — система делает их сама.

### 4. Android — ярлыки `activity-alias`

- В `AndroidManifest.xml` у `MainActivity` убирается фильтр `MAIN`/`LAUNCHER`. Вместо него — четыре `<activity-alias>` с `android:targetActivity=".MainActivity"`, `android:exported="true"`, своим `android:icon` и тем же фильтром `MAIN`/`LAUNCHER`: `.IconRing`, `.IconRingBlue`, `.IconCoins`, `.IconWallet`. `android:enabled="true"` — только у ярлыка иконки по умолчанию, у остальных `false`. Сама `MainActivity` остаётся: на неё по-прежнему указывают уведомления (`ReminderReceiver`) и `singleTop`.
- Ресурсы на каждый вариант: адаптивный значок `mipmap-anydpi-v26/ic_launcher_<id>.xml` (фон, рисунок, `monochrome` для «тематических значков» Android 13+) и PNG `mipmap-*/ic_launcher_<id>.png` 48–192 px для Android 7.x. Иконка по умолчанию остаётся под старым именем `ic_launcher` (на неё же ссылается `<application android:icon>`). У «Кольца на синем» фон — векторный рисунок с градиентом, у остальных — цвет `#F3F5F6`. PNG рисует ассистент из SVG раздела 9 безголовым Edge в scratchpad (как в шаге 7.2), в репозиторий — только готовые картинки.
- Kotlin: `set` сначала **включает** новый ярлык, потом **выключает** старый (`PackageManager.setComponentEnabledSetting(…, COMPONENT_ENABLED_STATE_ENABLED / DISABLED, DONT_KILL_APP)`). В таком порядке ни в какой момент не бывает «ни одного ярлыка». `current` смотрит `getComponentEnabledSetting` каждого ярлыка: явно включён — он; «по умолчанию» — значение из манифеста.
- Выбор, сделанный через `setComponentEnabledSetting`, система помнит и при обновлении APK поверх: манифест его не перебивает.

**Что увидит пользователь Android (честно, в тексте под списком вариантов):**

- **ярлык на рабочем столе может пропасть** — большинство оболочек (в том числе Pixel Launcher) удаляют ярлык выключенного компонента; иконка в списке всех приложений появляется новая через несколько секунд, ярлык на рабочий стол нужно перетащить заново;
- **приложение может закрыться** на некоторых оболочках производителей (MIUI, One UI старых версий), несмотря на `DONT_KILL_APP`; данные при этом не теряются — база пишется сразу при каждом сохранении;
- карточка в «Недавних» может исчезнуть.

Черновик текста под списком (утверждает пользователь): «На Android ярлык на рабочем столе может пропасть, а приложение — закрыться. Добавьте ярлык заново из списка приложений».

### 5. Экран: строка «Иконка приложения» в «Настройках»

- Группа «Внешний вид», после «Темы»: строка «Иконка приложения», справа — название текущей; касание открывает лист снизу с четырьмя вариантами (картинка 56–64 dp, название, галочка у текущей, скринридер — «выбрано»). Если система не умеет менять иконку (`supported == false` или канала нет — например, в тестах) — строки нет.
- Картинки для листа — четыре PNG 192 px в `assets/app_icons/` (рисует ассистент из того же SVG). Это ресурсы Flutter, не пакет.
- Касание по варианту → `set`; успех — галочка переезжает (после повторного `current`); отказ — сообщение «Не удалось сменить иконку». Повторное касание текущего варианта ничего не делает.
- Крупный шрифт: картинки не растут выше 64 dp, названия переносятся; тёмная тема — те же картинки (иконка на рабочем столе от темы приложения не зависит).

### 6. Правила на будущее

- `id` вариантов, имена ярлыков (`.IconRing` …) и имена наборов iOS **не переименовываются и не удаляются** — так же, как столбцы выпущенной схемы. Если ярлык, который сейчас выбран у человека, исчезнет из манифеста, приложение пропадёт из списка приложений Android. Убрать вариант можно только так: оставить ярлык в манифесте и при запуске переключать человека на иконку по умолчанию.
- Новый вариант иконки = новый `id`, новый ярлык, новый набор iOS, строчка в сторож-тесте.

## Последствия

**Проще:**

- выбор иконки без пакета и без новых зависимостей в Gradle и CocoaPods; ~40 строк Kotlin и ~30 строк Swift в уже существующих файлах;
- нет состояния в базе: показываем то, что действительно стоит на устройстве;
- сторож-тест ловит рассинхрон имён между Dart, Kotlin, Swift, манифестом и проектом Xcode, а проверка в облачной сборке — потерянные наборы иконок.

**Сложнее:**

- на Android смена иконки заметна неприятными побочками (пропадает ярлык, иногда закрывается приложение) — это системное ограничение, мы его только честно описываем;
- на iOS лишнее системное окно после смены — тоже не наше и не убирается;
- `flutter run` и `adb` запускают приложение через ярлык, а не через `MainActivity` напрямую — первым делом проверить на эмуляторе, что отладочный запуск и установка поверх работают (Flutter умеет находить `activity-alias`, но проверяем на нашей версии 3.47.5);
- картинки иконок (4 × 5 PNG для Android 7.x, 4 × 1024 для iOS, 4 превью) нельзя пересобрать одной командой — только перерисовать из SVG раздела 9 `docs/design-review-stage8.md` (так же, как в ADR 0013, п. 9);
- размер приложения вырастет примерно на 0,5–1 МБ (картинки 1024 на iOS).

**Риски:**

| Риск | Вероятность | Что делаем |
|---|---|---|
| Xcode в облаке не подхватил альтернативные наборы (опечатка в имени, не та настройка) — `setAlternateIconName` возвращает ошибку | средне | проверка `CFBundleAlternateIcons` в `ios-build.yml`; сторож имён; при ошибке — сообщение «Не удалось сменить иконку», приложение работает |
| После установки новой сборки поверх через Sideloadly iOS возвращает иконку по умолчанию | средне | это не ошибка: строка в «Настройках» читает систему и покажет правду; если так — пишем в `docs/how-to-iphone.md` |
| На Android приложение закрылось при смене иконки | средне (зависит от оболочки) | предупреждение под списком; данные не теряются; на эмуляторе Pixel_8 проверяем поведение и пишем в шаг, что увидели |
| `flutter run` / отладчик перестали находить, что запускать, после переноса фильтра на ярлыки | низко | проверка в первом же Android-шаге; если не работает — запасной вариант: фильтр `LAUNCHER` остаётся у `MainActivity` для иконки по умолчанию, а три ярлыка — только для остальных (тогда «по умолчанию» = «все три ярлыка выключены»), решение — новым дополнением к этому ADR |
| Будущее переименование ярлыка «уронит» иконку у человека | низко | п. 6 и сторож-тест |
| Вариант «Кошелёк» плохо читается на 29–48 px (мелкая застёжка) | низко | пользователь смотрит на эмуляторе и iPhone; при желании — упростить рисунок отдельным шагом |

## Отвергнутые варианты

1. **Пакеты смены иконки** (на pub.dev 2026-10-14: `flutter_dynamic_icon` 2.1.0 — последняя публикация 4 года назад; `dynamic_app_icon_flutter_plus` 2.2.1, `variable_app_icon` 0.0.3 — 2 года без обновлений, `launcher_icon_switcher` 0.0.2 и др., у большинства нет проверенного издателя). Делают то же самое (`setAlternateIconName` и `activity-alias`), но всё равно требуют ручной правки манифеста и проекта Xcode; самый популярный заброшен. Наш код — ~70 строк в двух файлах, которые уже есть.
2. **Хранить выбор в `app_settings` и применять при запуске.** Появляется второй источник истины, который расходится с системой (переустановка, сброс иконки iOS после обновления); применять при каждом запуске на Android — значит лишний раз дёргать ярлыки.
3. **Android: применять смену при уходе из приложения (`onStop`), а не сразу.** Приложение не закроется на глазах, но человек не видит результат сразу и не понимает, сработало ли; при выгрузке процесса в фоне смена может не примениться. Оставлено как запасной вариант, если на iPhone/Android пользователя закрытие окажется частым.
4. **Android: менять картинку ярлыка через `ShortcutManager` (закреплённые ярлыки).** Это отдельный ярлык рядом с приложением, а не иконка приложения; в списке приложений иконка не меняется.
5. **iOS: старый способ — отдельные PNG в бандле и ручной раздел `CFBundleAlternateIcons` в `Info.plist`.** Нужно добавлять файлы в цель Runner правкой `project.pbxproj` (несколько разделов), без Mac это легко сломать; набор в каталоге ресурсов — одна строка настройки.
6. **Скрыть системное окно iOS «Вы изменили значок».** Только через закрытые API — риск отказа при будущей публикации и поломки в новых iOS.
7. **Все 10 вариантов из раздела 9.** Пользователь выбрал четыре; каждый лишний вариант — +6 картинок и ярлык навсегда (п. 6).
