# 0006. Формат CSV-экспорта

- Статус: принято (все решения пользователя подтверждены 2026-10-04)
- Дата: 2026-10-04

Связанные решения: [0001](0001-local-storage-drift.md) (база, мягкое удаление, Auto Backup выключен), [0003](0003-dependencies.md) (свой CSV-кодек вместо пакета `csv`; `path_provider`, `share_plus`), [0004](0004-money-dates-recurring.md) (деньги и даты). План — `docs/ROADMAP.md`, «Мини-этап „Экспорт CSV“», шаги 6.1–6.3.

## Контекст

Экспорт CSV — **единственная резервная копия** данных: Auto Backup выключен, сервера нет. Значит, файл должен одновременно:

- читаться человеком в Excel и «Google Таблицах» (русская локаль);
- без потерь возвращаться в приложение будущим импортом (этап 6) — это и есть восстановление.

CSV (comma-separated values) — текстовая таблица: одна строка файла = одна строка таблицы, ячейки разделены разделителем. Запись и чтение уже делает наш кодек `lib/core/csv/csv_codec.dart` (шаг 6.1). Он работает только со строками; превращение сумм и дат в текст — задача экспорта.

Что важно из домена:

- `Transaction`: `id`, `type` (доход/расход), `amount` (`Money`: копейки + валюта, не отрицательная), `occurredOn` (локальный день), `occurredAt` (момент UTC), `categoryId`, `subcategoryId?`, `note?` (пустой комментарий уже превращён в `null`). Поля `createdAt`/`updatedAt` живут только в базе.
- Имена категорий **не уникальны**: правило `duplicateName` действует лишь среди **не архивных** категорий одного вида и уровня. Значит, возможны «Подарки» и в доходах, и в расходах, архивная «Кафе» рядом с новой «Кафе», одинаковые подкатегории у разных родителей. По одному имени категорию однозначно не найти.

## Решение

### 1. Общий формат (решения пользователя)

| Что | Как |
|---|---|
| Разделитель / перенос строки / кодировка | `;` / `\r\n` / UTF-8 с BOM (метка в начале файла, по ней Excel узнаёт кодировку) — делает кодек |
| Сумма | `350,00`: запятая, ровно две цифры копеек, без пробелов между разрядами. Считается целочисленно: `minor ~/ 100` и `minor % 100` с дополнением нулём до двух цифр. Без `double` и `NumberFormat`. **Для расхода** перед числом стоит знак минус — обычный ASCII-дефис `-` (U+002D), например `-350,00`; Excel читает его как число. Для дохода знака нет. Ноль — `0,00` без знака для любого типа (`-0,00` выглядит как ошибка). Изменение принято 2026-10-04 по просьбе пользователя; знак задаётся типом операции, а не полем суммы в домене |
| Дата | `ДД.ММ.ГГГГ` (`04.10.2026`), берётся из `occurredOn` — дня, каким его видел пользователь, а не пересчётом из UTC |
| Имя файла | `zuno-export-ГГГГ-ММ-ДД.csv`, дата экспорта — локальный день из `Clock` |

### 2. Один файл, первая строка — заголовки

Колонки по порядку (точные строки заголовков — часть формата):

| № | Заголовок | Значение | Пример |
|---|---|---|---|
| 1 | `Дата` | `occurredOn` | `04.10.2026` |
| 2 | `Тип` | `Расход` или `Доход` | `Расход` |
| 3 | `Сумма` | см. выше; в единицах валюты из колонки 4; у расхода — со знаком `-` | `-350,00` (расход), `350,00` (доход) |
| 4 | `Валюта` | код ISO 4217 | `RUB` |
| 5 | `Категория` | текущее имя категории | `Кафе` |
| 6 | `Подкатегория` | имя подкатегории или пусто | `Кофе` |
| 7 | `Комментарий` | `note` или пусто | `с Машей` |
| 8 | `ID операции` | `Transaction.id` (UUID v7) | `0192...` |
| 9 | `ID категории` | `categoryId` | `0192...` |
| 10 | `ID подкатегории` | `subcategoryId` или пусто | |
| 11 | `Время операции (UTC)` | `occurredAt.toIso8601String()` | `2026-10-04T09:15:00.000Z` |

Колонки 1–7 — для человека, 8–11 — технические, стоят в конце, их можно скрыть в Excel. Технические нужны, чтобы восстановление было **без потерь**:

- `ID операции` — повторный импорт того же файла не создаст дублей;
- `ID категории`/`ID подкатегории` — различают одноимённые категории (см. «Контекст») и позволяют импорту создать категорию **с тем же id**, сохранив структуру «категория → подкатегория»; вид категории следует из колонки `Тип`;
- `Время операции (UTC)` — без него пропадёт время суток и порядок операций внутри дня. ISO-строка, а не миллисекунды: Excel превратил бы длинное число в `1,79E+12` и испортил его при пересохранении.

`createdAt`/`updatedAt` **не выгружаем**: их нет в домене, а нужны они только для слияния при синхронизации, которой нет. Добавить колонку позже можно без поломки старых файлов (см. п. 6).

Отдельного файла категорий **нет**: один файл самодостаточен (так и задумано в ROADMAP: «одна кнопка, один файл»). Цена — в файл не попадают иконки, порядок, отметка «в архиве» и категории без единой операции; при восстановлении их придётся поправить руками. Если это станет важно, файл категорий добавляется позже, не меняя этот формат.

### 3. Какие строки попадают в файл

- Все **живые** операции (`deleted_at IS NULL` — так отбирает каждый запрос в `DriftTransactionsRepository`), **включая операции в архивных категориях и подкатегориях**: история должна остаться целой. Мягко удалённые — нет.
- Имена категорий берутся из списка всех не удалённых категорий, включая архивные (как `CategoriesRepository.watchAll`).
- Сейчас в `TransactionsRepository` нет метода «все живые операции» (`watchRecent` ограничен `limit`) — его добавляет шаг 6.2.
- Экспорт **всё или ничего**: если хоть одна строка базы испорчена (`DataCorruptedException`) или у операции не нашлась категория, файл не создаётся, пользователь видит понятную ошибку. Резервная копия, в которой молча не хватает строк, хуже, чем честный отказ.
- Операций нет — файл из одной строки заголовков.

### 4. Порядок строк: по возрастанию

`occurredOn`, затем `occurredAt`, затем `id` — от старых к новым. Это привычный вид журнала и выписки; новые операции при следующем экспорте дописываются в конец, и два файла легко сравнить; импорт идёт в хронологическом порядке. `id` в конце делает порядок полностью определённым: одна и та же база всегда даёт **побайтно одинаковый** файл, что упрощает тесты. «История» на экране показывает обратный порядок — это вопрос интерфейса, не файла.

### 5. Экранирование и пустые значения

- Кодек берёт поле в кавычки, если внутри есть `;`, `"`, `\r` или `\n`, и удваивает кавычку (`_encodeField` в `csv_codec.dart`). Комментарий `кофе; "булка"` + перенос строки + `и чай` запишется одним полем в кавычках, а `decodeCsv` вернёт его без изменений. В шаге 6.2 это проверяется тестом «туда и обратно» на уровне экспорта. Имена категорий экранируются так же.
- Пустой комментарий, отсутствующая подкатегория и её id — **пустая ячейка**, без `NULL`, без `""`. Excel покажет пустую клетку, а импорт превратит пустую строку обратно в `null` (как `normalizeTransactionNote`). Слово `NULL` после импорта стало бы настоящим комментарием «NULL». Потерь нет: в домене комментарий никогда не бывает пустой строкой, только `null`.
- Данные **не меняем** ради Excel. Комментарий, начинающийся с `=`, `+`, `-` или `@`, Excel может принять за формулу и показать `#ИМЯ?`. В самом файле текст цел, импорт читает файл, а не Excel. Это известное ограничение: апостроф в начале исправил бы показ, но испортил бы данные.

### 6. Совместимость с будущим импортом (этап 6, кратко)

- Импорт ищет колонки **по заголовку, а не по номеру**; лишние колонки пропускает. Поэтому добавить колонку можно без новой «версии», а переименовать или убрать — только через новый ADR.
- Обязательные колонки: `Дата`, `Тип`, `Сумма`, `Категория`. Необязательные: `Валюта` (по умолчанию `RUB`), `Подкатегория`, `Комментарий`, все `ID`, `Время операции (UTC)` (без неё момент вычисляется из даты). Так импорт примет и файл, написанный руками.
- Если `ID операции` уже есть в базе — строка считается уже загруженной и не дублируется (что делать с отличиями, решит проект импорта). Если `ID` нет — новая операция с новым id, а импорт заранее показывает, сколько строк добавит.
- Категория ищется по `ID категории`; если такого id нет — по виду (из `Тип`) и имени среди не архивных; если и так не нашлась — создаётся (с id из файла, если он есть).
- Сумму импорт разбирает `parseAmount`: после пересохранения в Excel `350,00` может стать `350` или `350,5`, и это нужно принять.

## Последствия

**Становится проще:**

- файл открывается в Excel без «кракозябр» и без настройки импорта, колонки понятны без инструкции;
- восстановление без потерь для самих операций: сумма, валюта, день, момент, категория, комментарий, id;
- формат расширяется добавлением колонок, старые файлы продолжают читаться.

**Становится сложнее:**

- 11 колонок вместо 7: технические видны человеку (их можно скрыть);
- при восстановлении теряются иконки, порядок, отметка «в архиве» и категории без операций;
- в коде появляется граница экспорта: превращение `Money` и `DateOnly` в строку, сборка строк, метод «все живые операции» в репозитории. Сборку строк делаем чистой функцией без Flutter и покрываем юнит-тестами. Файл пишется во временный каталог (`path_provider`, шаг 6.2) и отдаётся через `share_plus` (шаг 6.3).

**Риски:**

| Риск | Что делаем |
|---|---|
| Пользователь пересохранил файл в Excel: изменились суммы, кодировка, формулы | импорт терпим к `350`/`350,5` и файлу без BOM; в подсказке экспорта — «храните исходный файл» |
| Экспорт падает на одной испорченной строке | осознанно: отказ с понятным текстом лучше неполной копии |
| Имена категорий в файле — текущие, а не на момент операции | имена в истории и так не хранятся; связь держится на id |

## Отвергнутые варианты

**1. JSON вместо CSV.** Удобен машине и точно хранит типы, но не открывается в Excel как таблица, а пользователь хочет смотреть свои траты глазами. Импорт банковских выписок в будущем всё равно потребует CSV — два формата держать незачем.

**2. Сумма в копейках целым числом (`35000`).** Однозначно для программы, но человек в Excel видит суммы в 100 раз больше, а формула `СУММ` даёт копейки. Сумма со знаком (минус для расходов) сначала тоже была отвергнута из-за ADR 0004 (направление задаёт поле «доход/расход»); 2026-10-04 по просьбе пользователя минус для расходов в файле включён. Направление при этом по-прежнему задаёт колонка «Тип», знак — только для удобства чтения в таблице.

**3. Дата в ISO (`2026-10-04`) в колонке «Дата».** Сортируется как текст и однозначна, но русский пользователь и русский Excel привыкли к `04.10.2026` — решение пользователя. ISO оставлен только в технической колонке времени, которую читает программа.

**4. Excel-файл `.xlsx`.** Нужен пакет (например, `excel`), которого нет в ADR 0003: двоичный формат, тяжёлая зависимость и ещё один издатель, от которого зависит единственная резервная копия. CSV Excel открывает и так.

**5. Отдельный файл категорий (второй CSV).** Полностью восстановил бы иконки, порядок и архив, но требует хранить два файла вместе: сохранил один — копия неполная. Импорт тогда тоже должен выбирать два файла. Можно добавить позже, если понадобится.

**6. Только имена категорий, без id.** Короче, но неоднозначно (одноимённые категории в разных видах и в архиве), а повторный импорт создаст дубли операций.
